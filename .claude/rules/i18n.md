# I18N — runtime localisation

Format: `ID — rule. Why: … Enforced: mechanism (status).` Rationale: `docs/rationale/I18N.md`. Decision: ADR 007.

I18N-1 — Dictionaries are TypeScript const objects, one per locale, in a `scope:shared` project; `type Messages = DeepReadonly<typeof en>` with the base locale not declared `as const`; every other locale is declared `satisfies Messages`, and parameterised messages are typed functions. Why: missing or extra keys and wrong parameters are compile errors. Enforced: type (planned, ZMT-A-2).
I18N-2 — An I18nStore (SignalStore) holds the locale signal; `messages` is computed over the active dictionary and read directly by templates without an impure pipe; non-default locales load by dynamic import; plurals, dates and numbers use `Intl.PluralRules`, `Intl.DateTimeFormat` and `Intl.NumberFormat` bound to the locale signal. Why: switching locale is a signal change with no reload and no library. Enforced: review (planned). DEBT: backed by I18N-4 lint and I18nStore specs.
I18N-3 — `MatPaginatorIntl` and the `DateAdapter` locale follow the locale signal, and main-process menus and dialogs receive the locale over a typed IPC channel and read the same dictionaries. Why: the renderer, Material and native UI never show mixed languages. Enforced: test — Playwright smoke switching locale and asserting renderer and native menu labels (planned, ZMT-A-2).
I18N-4 — Templates contain no raw text nodes and no literal values in user-facing attributes (`aria-label`, `placeholder`, `title`). Why: untranslated text cannot land. Enforced: lint — workspace template rule in `tools/eslint-rules` (planned, ZMT-A-2).
