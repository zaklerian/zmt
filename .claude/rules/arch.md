# ARCH — architecture and code structure

Applies repo-wide. Format: `ID — rule. Why: … Enforced: mechanism (status).` Rationale: `docs/rationale/ARCH.md`.

ARCH-1 — Every Nx project carries exactly one `type:` tag (app, feature, ui, data-access, util, contracts) and one `scope:` tag (main, preload, renderer, shared), and depends only on projects the tag matrix allows. Why: layering and process isolation are checked on the project graph, not remembered. Enforced: lint — `@nx/enforce-module-boundaries` at error (active).
ARCH-2 — `type:ui` projects depend only on `type:ui`, `type:util` and `type:contracts`, inject no stores or services, and expose their API only through `input()`, `output()` and `model()`. Why: presentational components stay reusable and harness-testable. Enforced: lint — `@nx/enforce-module-boundaries` tag constraints (active).
ARCH-3 — Renderer code imports neither `electron` nor Node built-ins; `libs/contracts` is its only cross-process surface. Why: the renderer is sandboxed and must not reach privileged APIs. Enforced: lint — `no-restricted-imports` + `@nx/enforce-module-boundaries`; type — renderer tsconfig `types` excludes `node` (active).
ARCH-4 — Compiler strictness is repo-wide: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noPropertyAccessFromIndexSignature`, `verbatimModuleSyntax`, `noImplicitOverride`, plus Angular `strictTemplates`, `strictStandalone` and extended diagnostics as errors; `null` marks intentional absence, `undefined` marks never set. Why: the compiler catches unchecked index access, optional-field misuse and template type errors. Enforced: type — `tsconfig.base.json` + `angularCompilerOptions` (active).
ARCH-5 — Check values against types with `satisfies`; reserve `as` for an intended widening. Why: `as` silences the checker while `satisfies` keeps inference and checks. Enforced: lint — `@typescript-eslint/consistent-type-assertions` (objectLiteralTypeAssertions: never), `@typescript-eslint/no-unnecessary-type-assertion` (active).
ARCH-6 — Model closed sets as a `const` object with a `keyof typeof` derived union, not an `enum`. Why: const objects are plain data with no emitted runtime quirks. Enforced: lint — `no-restricted-syntax` on `TSEnumDeclaration` (active).
ARCH-7 — Every property of a declared interface or type literal is `readonly`, and every array type is `readonly T[]` or `ReadonlyArray<T>`; where a third-party API needs a mutable array, pass a `[...x]` copy. Why: mutating shared data becomes a compile error. Enforced: lint — `no-restricted-syntax` on non-readonly `TSPropertySignature`, bare `TSArrayType` and `Array<T>` (active); runtime backstop — SignalStore dev-mode freezing (active) and frozen IPC payloads (SEC-1, planned, ZMT-A-3).
ARCH-8 — Every promise is awaited, returned or explicitly marked `void`, and every rejection reaches a handler that updates state or logs. Why: floating rejections fail silently. Enforced: lint — `@typescript-eslint/no-floating-promises`, `@typescript-eslint/no-misused-promises` (active).
ARCH-9 — Every `index.ts` contains only `export * from './file'` lines, one per source file. Why: barrels stay passive aggregation with no curated surface to drift. Enforced: lint — `no-restricted-syntax` on named exports in `index.ts` (active).
ARCH-10 — File names carry a suffix naming the artifact kind: `.component.ts`, `.service.ts`, `.store.ts`, `.schema.ts`, `.model.ts`, `.const.ts`, `.util.ts`, `.guard.ts`, `.routes.ts`, `.spec.ts`; generator defaults produce these suffixes. Why: a file's kind is readable from its name and greppable workspace-wide. Enforced: lint — `check-file/filename-naming-convention` (active).
ARCH-11 — Files and folders are kebab-case. Why: one casing avoids case-collision bugs across filesystems. Enforced: lint — `check-file/filename-naming-convention`, `check-file/folder-naming-convention` (active). DEBT: `.scss` file names are not linted; a governance glob check would cover them.
ARCH-12 — Group files by subject domain and name a feature for the domain noun it owns; folders named after artifact kinds (`components/`, `services/`, `utils/`) are not used. Why: files that change together live together. Enforced: lint — `check-file/filename-blocklist` on artifact-kind folder paths (active).
ARCH-13 — Extract code to a shared library only when a third concrete consumer exists or is in active development, then confirm a stable surface, a domain-free core and real reuse value. Why: premature libraries freeze the wrong abstraction. Enforced: review (active). DEBT: CI script over the Nx project graph flags shared libraries with fewer than three dependents.
ARCH-14 — Imports and object keys are sorted alphabetically by the autofixer; meaningful order is kept through a named override. Why: deterministic order removes diff noise and ordering debates. Enforced: lint — `perfectionist/sort-imports`, `perfectionist/sort-objects` (active).
ARCH-15 — Types and classes are PascalCase, functions and variables camelCase, module-level runtime constants SCREAMING_SNAKE_CASE. Why: a name's casing signals its kind. Enforced: lint — `@typescript-eslint/naming-convention` (active).
ARCH-16 — Dev builds switch to a separate `userData` directory at startup, before anything is persisted. Why: development runs must not touch the production store on the same machine. Enforced: test — main-process startup spec (planned, ZMT-A-3).
ARCH-17 — Inline lint configuration is disabled; every exception is a named override block in `eslint.config.mjs` (`name: "ZMT-A-<N>: <reason>"`, narrowest `files` glob). Why: every exception is visible, ticket-linked and reviewable in one place. Enforced: lint — `linterOptions.noInlineConfig: true`, `reportUnusedDisableDirectives: "error"` (active).
