# AI — how Claude Code works in this repo

Applies repo-wide. Format: `ID — rule. Why: … Enforced: mechanism (status).` Rationale: `docs/rationale/AI.md`.

AI-1 — Every rule states its enforcement (lint, hook, type, test or review) and status, and a review-only rule carries a `DEBT:` note naming the mechanical enforcement it lacks. Why: declaring the mechanism exposes which rules rely on memory. Enforced: hook — governance check in `verify.sh` (active).
AI-2 — Rules are written as directives with a one-line why and no all-caps emphasis. Why: a directive shapes output at generation time, and a stated why lets edge cases be judged. Enforced: review (active). DEBT: governance check flagging all-caps words and filter-phrased openers in `.claude/rules`.
AI-3 — Trigger text matches content: a skill's description, a rule file's `paths` frontmatter and a doc heading change in the same edit as the body they describe. Why: stale triggers load the wrong guidance or none. Enforced: review (active). DEBT: rule-reviewer compares skill description keywords with body headings whenever `.claude/skills` changes.
AI-4 — Default to critique: find where a design, prompt or rule is wrong, and when nothing is, say so plainly without padding. Why: validation adds no information. Enforced: review (active). DEBT: prompt-type Stop hook checking that review replies name risks or state none were found.
AI-5 — Agreement covers only the item under discussion; adjacent decisions stay as they are until addressed. Why: implied agreement silently widens scope. Enforced: review (active). DEBT: rule-reviewer flags changed files outside the prompt's declared file list.
AI-6 — When an instruction conflicts with a rule, ADR or ledger line, stop, name the conflict by ID or date, and act only after the owner acknowledges it. Why: reversals happen deliberately or not at all. Enforced: review (active). DEBT: governance check requiring a ledger line in any change that edits `.claude/rules` or `docs/adr`.
AI-7 — Clarifying questions are numbered Q1, Q2 … and the numbering continues across the thread. Why: answers stay compact and unambiguous. Enforced: review (active). DEBT: prompt-type Stop hook checking Q-numbering in multi-question replies.
AI-8 — Task prompts carry only the task delta and cite rules by ID instead of restating them. Why: restated rules drift from the source. Enforced: review (active). DEBT: prompt linter rejecting text copied from `.claude/rules`.
AI-9 — Each prompt sentence is an imperative, a constraint, a specification, a verification step or a scope guard; decided items are instructions, and open ones are A/B options with selection criteria. Why: hedged prompts invite broad search and false positives. Enforced: review (active). DEBT: prompt linter flagging rationale prose and hedge words.
AI-10 — Implementation prompts describe intent (goal, files, shape, behavior, rule IDs, verification) and contain no code; documentation prompts paste the content when the prose is the deliverable. Why: the agent owns the code, and the owner owns the prose. Enforced: review (active). DEBT: prompt linter rejecting code fences in implementation prompts.
AI-11 — Prompts follow goal, numbered steps, constraints and rule IDs, and end with Definition-of-Done commands; scope guards are added only where drift has been observed. Why: verification is part of the task, not an afterthought. Enforced: review (active). DEBT: prompt linter checking section headings and a trailing DoD block.
AI-12 — The repo map in `CLAUDE.md` lists every Nx project and changes in the same PR as the layout. Why: a stale map sends work to the wrong place. Enforced: hook — governance check comparing `nx show projects` with `CLAUDE.md` (planned, ZMT-A-2).
AI-13 — Claude Code adds no comment lines to `.ts`, `.html` or `.scss` files, including `@ts-expect-error` and `/// <reference>`; existing human comments stay untouched. Why: names and types carry intent, and exceptions are human decisions. Enforced: hook — PreToolUse `no-new-comments.sh` blocks Edit, Write and MultiEdit that add comment lines (active).
