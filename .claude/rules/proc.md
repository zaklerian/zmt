# PROC — process

Applies repo-wide. Format: `ID — rule. Why: … Enforced: mechanism (status).` Rationale: `docs/rationale/PROC.md`.

PROC-1 — Work happens on `dev/ZMT-A-<N>` or `hotfix/ZMT-A-<N>` (subtasks `ZMT-A-<N>.<M>`, cleanup tickets `ZMT-A-D<N><letter>`), branched from updated `main`; `main` changes only through a PR. Why: every change is traceable to a ticket and reviewed. Enforced: hook — PreToolUse `check-branch.sh` blocks Edit, Write and MultiEdit on any other branch (active); lefthook pre-push blocking non-ticket branches and pushes to `main` (active).
PROC-2 — A commit's first line is the ticket ID; body lines start with `+` added, `-` removed, `*` changed, `~` fixed, `!` breaking. Why: history stays scannable and greppable by ticket. Enforced: hook — commitlint custom plugin via lefthook commit-msg (active).
PROC-3 — One ticket maps to one PR; the commit ticket ID equals the branch ticket ID, and prep work becomes a subtask with its own PR. Why: each PR is reviewable and revertible as one decision. Enforced: hook — commitlint plugin comparing the commit ID with the branch (active).
PROC-4 — A task is done only when its prompt's Definition-of-Done commands pass; the Stop hook runs the governance checks and `nx affected -t lint typecheck test`. Why: "done" is a verified state, not a claim. Enforced: hook — Stop `verify.sh` (active).
PROC-5 — Write an ADR when a decision has more than one defensible answer, spans several parts of the codebase, or is likely to be revisited; an ADR is at most 25 lines with Context, Decision and Consequences. Why: decisions stay short enough to be read. Enforced: hook — governance check (active).
PROC-6 — Every decision gets one ledger line `date · decision · ADR link`, and a deferred decision names its trigger as `revisit: <condition>`. Why: deferrals return to discussion on a named condition instead of drifting. Enforced: hook — governance check (active).
PROC-7 — Sprint work follows planning → prompt → Claude Code → review → MERGED, and every hand-off ends with the status line from `docs/sprint-protocol.md`. Why: whoever holds the ball is always explicit. Enforced: review (active). DEBT: prompt-type Stop hook asserting that the final message ends with a STATUS line.
PROC-8 — Retros use five sections (Went Wrong, Could Be Better, Good, Keep Doing, Action Items), and each action item names an owner and a trigger. Why: every observation ends in a commitment. Enforced: hook — governance check on `docs/retro/*.md` (active).
PROC-9 — A review finding seen three times becomes a rule with mechanical enforcement, and a costly defect class becomes one on first occurrence; ledger lines for findings carry `finding:<slug>`. Why: recurring defects end in mechanisms, not reminders. Enforced: hook — governance check fails when a slug reaches three ledger lines without a rule ID (active).
PROC-10 — A commit touching more than one Nx project or top-level area, or more than five files, uses a multi-line body (Option B); otherwise a single line (Option A). Why: the commit's shape matches its breadth. Enforced: hook — commitlint plugin reading the staged diff (active).
