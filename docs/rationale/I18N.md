# I18N — rationale

Long-form reasoning for the rules in `.claude/rules/i18n.md`, keyed by rule ID. Decision: ADR 007.

## I18N-1 — Typed dictionaries

A dictionary is a plain TypeScript object, so the compiler checks translations without a library. `Messages` is derived from the base locale with widened strings. The base is not declared `as const`, because literal string types would make every other locale fail `satisfies`. It is wrapped in `DeepReadonly` so dictionaries stay immutable (ARCH-7).

Each other locale is declared `satisfies Messages`, so a missing key, an extra key or a wrong function signature is a compile error in that locale's file. Parameterised messages are functions, so arguments are typed and ordering follows each language's grammar. Dictionaries live in a `scope:shared` project because main-process menus and dialogs need them too.

## I18N-2 — Runtime store

Locale switching is a signal change. The store holds the locale, and `messages` is a `computed()` over the loaded dictionary. Templates read `messages().some.key` directly, so a switch re-renders exactly the bindings that read messages; impure pipes would be re-run on every check. Non-default locales load through dynamic import, so the startup bundle carries one dictionary. Pluralisation, dates and numbers use `Intl` APIs bound to the locale signal, which covers CLDR rules without a formatting library.

This is review-only today; I18N-4 lint and I18nStore specs back it mechanically.

## I18N-3 — One locale everywhere

Material components carry their own strings (paginator labels, datepicker formats). `MatPaginatorIntl` must emit its change notification and the `DateAdapter` must be re-localised on every switch, or they stay in the old language. Native menus and dialogs are built in main, so main receives the locale over a typed IPC channel and reads the same dictionaries. The Playwright smoke switches locale and checks both renderer text and native menu labels.

## I18N-4 — No raw template text

A text node or a literal `aria-label` is a string that never passes through a dictionary. A workspace template lint rule flags non-whitespace text nodes and literal user-facing attributes, making I18N-1's compile-time checking complete: every visible string comes from `messages()`.
